# 子任务入口（给 omp 子代理 / Codex 等执行者）

本文件**不是**规范的第二份拷贝。规范只有一份：`AGENTS.md` 与 `docs/CONVENTIONS.md`。
这里只回答三件事：开工前读什么、哪些事绝对不能做、交付时怎么写。

**冲突时优先级**：`AGENTS.md` > `docs/CONVENTIONS.md` > 本文件。

---

## 1. 开工前必读（按顺序，不可跳过）

1. `AGENTS.md`（仓库根目录，全部）
2. `docs/CONVENTIONS.md` 中与本次改动相关的章节
3. `docs/HANDOFF.md` 的「进度矩阵」与「已知缺口」，确认你要做的东西没被做过
4. 涉及具体模块时读该模块源码；涉及外部协议时先看 `docs/SPIKE-REPORT.md` 里是否已有实测结论

子代理不继承父会话上下文，任务描述必须自包含。如果任务文本与上述文件冲突，停下来问，不要猜。

---

## 2. 硬约束（违反即失败）

- **范围**：只改任务指定的文件与行为；不顺手重构、不改无关格式、不改依赖版本。
- **边界**：遵守 `AGENTS.md` 的 crate 依赖方向；新 crate 必须先出现在架构文档里。
- **风格**：代码/注释/提交信息英文，文档中文；格式以 `rustfmt.toml` 为准。
- **错误处理**：库 crate 不用 `anyhow`；非测试代码不用 `unwrap`/`expect`（不变量除外并写明）。
- **安全**：凭据只走 `SecretStore`；日志禁止出现密码、令牌、完整邮箱、正文；HTML 必须走统一净化。
- **不写版本计划**：禁止引入 v1/v2/MVP/后续迭代式的分层或文档。
- **不提交**：`target/`、`spike/data/`、生成的绑定、数据库文件、任何密钥。
- **不擅自** `git commit` / `git push` / 改远端，除非任务明确授权。

执行中**不要**反复跑全量构建与测试；改完后统一验证一次，避免浪费时间。

---

## 3. 验证要求

完成任务后必须实际运行改动路径，而不是只编译：

```bash
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

涉及 IMAP 的行为改动，还需按 `docs/IMPLEMENTATION.md` §4 起 Dovecot 做一次冒烟。
无法验证的部分，明确写“未验证”和原因，不得写成已验证。

---

## 4. 交付格式（回复必须包含）

```
# 改动
- 文件 → 行为变化（一句话一条）

# 验证
- 命令 → 关键输出摘要（真实运行过的）

# 未验证 / 风险
- 具体项 → 原因 → 需要什么条件

# 对文档的影响
- 需要更新的文档章节（若已更新，注明）
```

不要用“应该可以”“理论上”代替实跑结果。

## 5. 任务模板（父代理派发时直接粘贴）

```markdown
# Target
文件/模块：
非目标：

# Context
必读：AGENTS.md、docs/CONVENTIONS.md、docs/HANDOFF.md 相关段落
当前行为：
期望行为：

# Change
1. …
2. …

# Constraints
- 不改动：…
- 边界：…
- 依赖：不新增 / 允许新增（需说明理由）

# Acceptance
- 可观察结果：…
- 必须跑的命令：cargo fmt / clippy / test（以及 Dovecot 冒烟，若涉及协议）
- 不得出现：新增 warning、未使用代码、TODO 占位
```

---

## 6. 常见误判

| 情况 | 正确做法 |
|---|---|
| 任务要求与 AGENTS.md 冲突 | 停下来说明冲突，不自行取舍 |
| 发现无关的坏味道 | 记录到交付的「风险」里，不动手 |
| 测试需要真实服务器 | 用环境变量开启，默认跳过；不要改测试去适配环境 |
| 不确定某平台是否可行 | 标“未验证”，不要凭经验断言 |
| 想加一个小依赖图省事 | 先确认标准库/现有依赖不可行，再按依赖政策评估 |
